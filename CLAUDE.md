# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Qullamaggie-style momentum scanner for US and India (NSE) equities. `SPEC.md` is the source of truth for rules, thresholds and the build phases; work through the phases one at a time, using plan mode before each.

## Ground rules (from SPEC.md)

- Read-only market data. No broker integration, no order placement, no credentials in the repo. Secrets go in `.env` (gitignored) and GitHub Actions secrets.
- Every threshold is a tunable default and lives in `config/<market>.yaml`, never in code. In the YAML, `(SPEC)` marks the user's numbers and `(assumption)` marks Claude's choices. Keep labelling new values that way and tell the user which numbers are assumptions.
- Explain every formula in a code comment. Write unit tests for every indicator.
- Commit after each working step. Never rewrite working code without saying why.
- Output is information, not investment advice.

uv run --env-file .env python -m scanner.notify --chat-id                # find TELEGRAM_CHAT_ID
uv run --env-file .env python -m scanner.notify --test                   # send a test message

Other CLI flags: `--scan all|leaders|watchlist|breakouts`, `--window 1m|3m|6m`, `--mode fixed|rank`, `--refresh` (re-run today's incremental update), `--limit N`, `--csv PATH`, `-v`.

## Architecture

Data flows: universe loader → `PriceProvider` → parquet cache (long format) → `Panels` (wide) → indicators → scans → CLI.

- **Two price shapes** (`scanner/data/base.py`). *Long* rows (`symbol, date, open, high, low, close, volume`) are what providers return and the cache stores. *Panels* are wide date × symbol DataFrames, one per field; indicators and scans use these so every symbol is computed at once. `Panels.from_long` builds the trading calendar from dates where ≥50% of the median symbol count has a bar, so a stray holiday bar from one ticker can't shift every "n bars ago". Missing bars stay NaN on purpose (no forward-fill).
- **Scans are market-agnostic** (`scanner/scans.py`). Every rule is computed as a date × symbol frame (`liquidity_frames` → `leader_frames` → `setup_frames`); results are read off the *last row*. `run_scans` builds the frames once on a short tail of the panels (`_rows_needed`) and returns leaders, watchlist and breakouts together, and the CLI uses only `run_scans`. Rolling means over different tail lengths differ by ~1e-15, so compare tables with a tolerance in tests. `panels.as_of(date)` is how point-in-time / no-lookahead evaluation works, and the Phase 5 backtest should reuse it. Use `traded_value` / `min_avg_traded_value` (dollar volume in the US, turnover in India), not market-specific names.
- **Watchlist / breakout rules** (`_watch_state`): a name is on the watchlist at day *t* if its setup qualified within the last `watchlist_memory_sessions` (5), it hasn't closed above that day's trigger since, and the *structural* rules (Stage 1 liquidity on *t* itself via `setup.require_liquid_today`, leader in the last 20 sessions, close > SMA50, SMA10 > SMA20, within 15% of the 20-day high) still hold at *t*. The noisy rules (higher lows, tight range, volume dry-up) may lapse within the window. **A breakout on *t* requires being on the watchlist at *t−1*.** The trigger comes from the setup day, the watchlist stop is the latest low, and the breakout stop is the breakout day's low. Average volume always means the 20 sessions *before* the bar (`indicators.prior_mean`). `tests/synth.py` holds the hand-checked "textbook" setup used by the setup and breakout tests.
- **Indicators** (`scanner/indicators.py`) accept a Series or a panel and require full windows (`min_periods = n`).
- **Market adapters** (`scanner/data/us_loader.py`, `scanner/data/india_loader.py`) supply `load_universe(cfg)`, `make_provider(cfg)` and `chart_url(...)`; India also supplies `latest_day_fetcher(cfg)`. `scanner/run.py` maps `--market` to an adapter via `MARKETS`. Universe caching is shared (`cache.load_cached_universe`). Tables and alerts show the exchange's own symbol (`source_symbol`: RELIANCE, BRK.B), not Yahoo's; rupee amounts are in crore/lakh (`notify.money`).
- **yfinance** lives only in `scanner/data/yfinance_provider.py`, behind the `PriceProvider` protocol, so a paid provider can replace it. It calls `yf.download(auto_adjust=False)` and uses OHLCV as returned: split-adjusted, NOT dividend-adjusted (deliberate choice; `Adj Close` is ignored). A batch where every ticker fails is treated as rate limiting and retried with backoff; partial failures get one leftover pass.
- **Cache** (`scanner/data/cache.py`, files under `data/cache/<market>/`, gitignored): `prices.parquet`, `universe.csv`, `meta.json`. Updates re-download a 150-bar overlap, which covers the 126-bar 6M window, so a split Yahoo records late is still caught. If an overlapping close differs by >0.5% (a split re-adjusts all of Yahoo's history), that symbol's full history is re-downloaded. `meta.json["checked"]` records per symbol the last cutoff it was updated against (only when the download actually contained a bar for that cutoff, so a same-day retry re-downloads what wasn't published yet); per-symbol tracking keeps a `--symbols` run from making a full run skip other names. Writes are atomic (temp file + `os.replace`) and the first download checkpoints every 10 batches.
- **One-day-move flag**: names whose 6M window contains a one-day move of at least `flag_day_move_multiple` (US 3×; India 1.3×, i.e. beyond NSE's 20% band) are marked ⚠; flag only, never excluded (user decision). These are real squeezes or reverse splits Yahoo hasn't adjusted yet; the first full run found CHOW (~10× overnight) and VCIG (~20×), with no split recorded on Yahoo.
- **India data (NSE)**: universe = `EQUITY_L.csv`, series EQ only; prices = Yahoo `SYMBOL.NS` (split/bonus-adjusted). Yahoo's daily NSE candles arrive a day or more late (Friday 2026-11-13 appeared 22–37 h after the close), so `cache.fill_missing_sessions` fills sessions Yahoo hasn't published from NSE's own end-of-day file (`scanner/data/nse_bhavcopy.py`, UDiFF bhavcopy; 404 = no session). It matched Yahoo exactly on 2026-11-12 (604/604 liquid stocks) and gave an identical scan for 2026-11-13. Yahoo rows replace filled ones when they arrive. Bhavcopy is unadjusted; a corporate action on a filled day shows as a ⚠ jump until Yahoo's re-adjusted history triggers the overlap re-download.
- **Circuit lock (India, SPEC)**: `indicators.circuit_locked` (range ≤ 0.1% and |move| ≥ 1.9%) + `run_length`; Stage 1 fails if a streak of ≥2 locked sessions ended in the last 10 (`liquidity.exclude_circuit_locked`, off for US).
- **Data-quality report** (`scanner/quality.py`, `--quality [--check-splits]`): jumps beyond the flag threshold with nearest clean bonus/split ratio, volume change and Yahoo's split record; missing sessions; frozen streaks; zero-volume bars; stale symbols.
- **Partial bars**: `last_complete_session_date` drops today's bar until market close + `close_buffer_minutes` in the exchange time zone from config.
- **Config** (`scanner/config.py`): strict pydantic models (`extra="forbid"`), so a misspelled YAML key is an error, not a silent default.
- **US universe filter**: Nasdaq Trader `nasdaqlisted`/`otherlisted`, keeping NASDAQ/NYSE/NYSE American and dropping ETFs, test issues and the regex patterns in `us.yaml`. The name regexes were tuned against the real files; `tests/fixtures/*_sample.txt` pins real false-positive cases (e.g. "Preferred Bank", ADRs with "right to receive", MLP "Common Units"). Re-check against the live files when changing patterns.
- **Alerts** (`scanner/state.py`, `scanner/notify.py`): `state/<market>.json` (committed, one file per market) records the last *sent* run. "New" means on today's watchlist but not on the last sent one, plus all of today's breakouts. "Too wide" breakouts (stop wider than one ADR, which SPEC rejects) are named in their own section when `alerts.list_wide_breakouts` is on (user decision, both markets). The same market date skips silently (holidays, reruns), an older date is refused, and fewer than `alerts.min_active_ratio` × last run's active symbols triggers a warning with no state change. The first run sends the full watchlist and records it as the baseline. Breakouts on sessions missed since the last sent run (outage, late data) are evaluated point-in-time and listed under dated headings (`scans.missed_breakouts`, up to `alerts.catch_up_max_sessions`). State is saved only after Telegram delivery succeeds, never on `--dry-run`. A real `--alert` run refuses `--symbols/--limit/--as-of`. The bot token is part of every Bot API URL, so `TelegramNotifier.scrub` removes it from all error text; keep it that way.
- **GitHub Actions** (`.github/workflows/scan-us.yml`, `scan-india.yml`): US cron 22:23 UTC Mon–Fri; India 12:41 UTC (18:11 IST) plus a 14:17 UTC retry that sends only if the first run didn't (same market date skips). Cron minutes are odd on purpose: GitHub delays or drops scheduled runs at busy round times (a 22:00 run started 4 h late; a 12:30 run hadn't started after 25 min), so keep them off :00/:15/:30/:45. **Primary trigger is outside GitHub**: cron-job.org POSTs a `workflow_dispatch` (`{"ref":"main","inputs":{"dry_run":"false"}}`) at 18:00 Asia/Kolkata and 17:00 America/New_York, Mon–Fri, using a fine-grained token (Actions: read/write, this repo only) that lives only in cron-job.org; dispatched runs usually start within seconds, while scheduled ones ran hours late or not at all (on 2026-11-16 none fired; that day a dispatched US run also sat queued while Actions was backed up). The cron schedules are the backup. Setup and token renewal: `docs/external-scheduler.md`. A `full_watchlist` dispatch button sends the whole watchlist. The price cache lives in the Actions cache (new key per run, restore newest); `state/<market>.json` is committed back by github-actions[bot]. Manual dispatch defaults to dry run. Secrets: `TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`. The repo is public: never commit `.env`, tokens or cache files.
- **Backtest** (`scanner/backtest.py`): `history_frames` computes the live rule frames once over all history (every rule is causal), `trigger_events` walks each day: names on day t−1's watchlist whose high reached the trigger. `verify_against_live` re-runs the live scanner on truncated data and must match; it runs inside every backtest. Model A = buy-stop at max(open, trigger), stop = day low from the next day; Model C = A, but a fill that fails by the close is sold at that close; Model B = next open after a confirmed breakout (skip if it opens at/below the stop). **Sizing and R must use only what is known at entry**: A/C use the previous day's low (the watchlist stop) because the breakout day's low is only known after the fill; B uses the breakout day's low. Two look-ahead bugs were caught this way (volume-ordered fills, day-low sizing), each of which had produced a fake +50–80%/yr. SPEC exits (stop / partial after N days / SMA trail) for the 8-combination grid; the headline exit is fixed in config *before* looking at results. Model A/C's ok/too wide/failed split uses the day's close and volume, so it is hindsight (marked †); only "A · all" and "C · all" are tradeable. Equity curve: risk-based sizing with `min_risk_pct` floor, no leverage, Model A/C same-day fills in a seeded random order (the day's volume is known only after the fill). All equity curves and the benchmark start on the first signal day. First results (2022-07 → 2026-11): every tradeable variant lost after costs in both markets and trailed the index; see `reports/`. **Market filter test** (`backtest.market_filter_sma` = 50: trade only if the benchmark closed above its 50-day SMA on the session before entry; rule and pass mark, positive mean per trade *and* CAGR above the index, fixed before running; reported in its own section, unfiltered tables unchanged): failed in both markets. In the US it trimmed losses; in India the trades it removed did better than the ones it kept. Don't keep tuning filters on the same 2022–2026 data: every extra variant tried raises the chance of a lucky-looking result.
- **Dashboard** (`scanner/dashboard.py`): real `--alert` runs write a deterministic `site/data/<market>.json` (committed with the state file); the `publish` job in each scan workflow rebuilds the self-contained site from latest `main` and deploys it to GitHub Pages (https://asees543.github.io/momentum-scanner/). Dry runs and full-watchlist runs don't publish.
- **Research notes** (`docs/swing-method-research.md`, 2026-11-16): a review of published evidence, written after the backtests failed. Short-hold, tight-stop breakout trading has no rigorous support; momentum held for months and long-trend following with wide stops do. Proposed next tests, in order: do the leaders beat the index over 1–3 months (diagnostic), monthly momentum rotation, long-trend version. Rules are to be copied from published sources and fixed before running, with more history and a hold-out period. None of it is built yet.
- **Study set** (`scanner/study.py` → `study/<market>.html`): past trigger touches as chart cards, for practising Qullamaggie-style selection (user asked 2026-11-17). `study_trades` reuses the backtest's Model A trades with the headline exit, so a card's result is the number behind "A · all". Decks: a random sample of all triggers (the only fair one for scoring picks against taking everything), the biggest winners (one per symbol per move), failed triggers, and confirmed breakouts that lost. Counts, chart window and seed are in `study:` in the YAML (all assumptions). ⚠-flagged, still-open and too-recent trades are left out. **Practice mode must not leak the future**: the bars drawn, the price and volume scales and the empty space on the right all use only bars before `cut` (the trigger day), and the symbol and year stay hidden until the take/skip choice. Charts use a log price scale. Answers live in the browser's localStorage. **Local only**: the page embeds price history and the repo and site are public, so `study/` is gitignored; don't commit or publish it. To preview in the Browser pane, copy the built pages to the scratchpad and serve from there (the preview server can't read ~/Desktop).
- **Both-screens list** (`scans.jack_pass` / `jack_screen`, `jack:` in the YAML; user asked 2026-11-20): names that are on one of our lists (breakout, watchlist, or a leader today) AND pass the filters read from a screenshot of Jack Corsellis's screener: close > 21-day EMA, > 50-day SMA, > 200-day SMA, 20-day ADR > 4%, 50-day average dollar volume > 250M (all strict; the 50-day value shown is that screener's, not our 20-day one). `run_scans` returns it as `ScanResults.jack` (None only in hand-built test results). It is shown as its own dashboard panel (`snapshot()["jack"]`; snapshots written before it existed still build) and as a "🎯 On both screens" section at the end of every alert message, listing ALL such names each day, not only new ones, or "None today"; it does not affect the state diff or whether a message is sent. **India's volume floor is an assumption:** Rs 120 crore, chosen by rank (250M is the top 10.5% of the liquid US names; the same share of the liquid India names starts at about Rs 119 crore on 2026-11-13 data), because 250M dollars is about Rs 2,200 crore and no liquid India name reaches it. Of the 20 US names passing their screener alone, only 3 were also on our lists on 2026-11-13 (India 16 of 30). The screenshot may show an example setting rather than their daily screen, and their presets and lists are not visible.
